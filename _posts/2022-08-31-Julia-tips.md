## Show

For custom pretty printing, redefine `Base.show`:

```Julia
function Base.show(io::IO, v::YourType)
    print(io, "compact description of your type, to be used when in array etc.")
end

function Base.show(io::IO, ::MIME"text/plain", v::YourType)
    show(io, v) # Reuse compact description
    print(io, "\nExtended description used when displaying value in REPL.")
    show(io, MIME("text/plain"),  v.field_with_existing_description)
end
```

## Check size of an object
Display object size in bytes:
```Julia
Base.summarysize(object)



macro size(expression)
    quote
        value = $expression
        size_B = Base.summarysize(value)
        si_prefix = Dict(0=>(0,""), 1=>(3,"K"), 2=>(6,"M"), 3=>(9,"G"), 4=>(12,"T"))
        order = floor(Int, log(10, size_B))
        exponent, my_prefix = get(si_prefix, floor(Int,order/3), (0, ""))
        println("'", $(Meta.quot(expression)), "' size is ", round(size_B/10^exponent; digits=2), " ", my_prefix,"B")
        size_B
    end
end

@size object
```

## Logging
See [docs](https://docs.julialang.org/en/v1/stdlib/Logging/). 

Log messages and basic syntax:

```Julia
@debug "Warning"
@info "Info, $(5+sum(a)/3)"
@warn "show some variables" A b=sum(c) D
@error
```

Loggers process the messages. They can filter messages generated by the code and present them in a specific way. Example logging into file:

```Julia
using Logging
io = open("log.txt", "w+")
logger = SimpleLogger(io)

# Create a ConsoleLogger that prints any log messages with level >= Debug to stderr
debuglogger = ConsoleLogger(stderr, Logging.Debug)

# Enable debuglogger for a task
with_logger(debuglogger) do
    @debug "a context specific log message"
end

# Set the global logger to logger
global_logger(logger)

# Write all buffered messages to the file
flush(io)

# Close the file
close(io)
```

## Benchmarking Julia

Basic benchmarking in Julia is done with `@btime` macro from `BenchmarkTools.jl.`

The overview of benchmarking tools:

- [BenchmarkTools.jl](https://github.com/JuliaCI/BenchmarkTools.jl) 
  - Contains fundamental benchmarking tools and terminology. 
  - offers the `@btime` macro for quick basic benchmarking of functions
  - `@benchmark` macro for more detailed benchmarking,
  - Allows definition of `BenchmarkGroup` that is the basis for the benchmarks in the following packages
- [PkgBenchmark.jl](https://github.com/JuliaCI/PkgBenchmark.jl)
  - Contains tools for benchmarking packages and their commits
  - Can automatically run `BenchmarkGroups` defined in package `benchmark/benchmarks.jl` file from outside the package, for different commits
  - Can be used in CI, also usable for local benchmarking
  - Works ONLY with code that is committed, does not work with dirty directories. 
- [AirspeedVelocity.jl](https://github.com/MilesCranmer/AirspeedVelocity.jl)
  - terminal-based benchmarking tool for benchmarking commits inside published packages, can also be used in CI
  - not suitable for local benchmarking of in-development code

### Benchmark basic terminology
The `BenchmarkTools.jl` [manual](https://juliaci.github.io/BenchmarkTools.jl/stable/manual) is a good starting point. Few notes on the terminology of "trial", "sample" and "evaluation":

The benchmark you run is a `Trial`. This trial measures averages from multiple "samples". Sample is a single time/memory measurement of the function. To reduce impact of the noise, multiple samples are taken and averaged. 

However, if you are benchmarking a really fast code, the code might finish running faster than the resolutoin of your timer. In that case, each "sample" runs the function in multiple "evaluations" and dividies the total runtime by the number of evaluations. This approximates the "sample" time.

However, for long-running funcitons in package-wide benchmarks, **the "sample" will only contain one "evaluation"**. 

The "tuning" mechanism in `BenchmarkTools.jl` is essentially used to adjust the number of evaluations in each sample, so that it is consistent between benchmarks.

The resulting numbers from multiple samples then need to aggregated. There are several options, but median is a safe bet, [the docs cover the different options quite nicely](https://juliaci.github.io/BenchmarkTools.jl/stable/manual/#Which-estimator-should-I-use?). 

### Interpreting the results
First of, I found it useful to run the `BenchmarkTools.jl` `@benchmark` macro on the function I am benchmarking to get a feel for the distribution of the samples. After that, I can decide to add the function to a benchmark group. 

After runnin the benchmark group, I can use the `BenchmarkTools.ratio` or `judge` function to compare the results of the benchmarks.

By default, the tolerance for improvement in time is 5%, and for memory 1%.

### Benchmarking package perormance with PkgBenchmark.jl and BenchmarkTools.jl

The basic workflow would be to prepare a `BenchmarkGroup` in the package, and run the relevant group manually as you go to help development. Then, when you commit, run all the benchmarks with `PkgBenchmark.jl` with every commit, checking for performance regressions. 

However, if you want to add new benchmarks to the package or upgrade the benchmarking code, you will need to rebase the tested commits on top of the updated benchmarks to use `PkgBenchmark.jl`. 

So, my workflow is following:

1. edit/create benchmarks in `/benchmark/benchmarks.jl` and commit them to a benchmarking branch
2. `git rebase` the branch with commits I want to evaluate on top of the changes to the benchmark
3. `] dev MCTS` in the benchmarking environment, use `PkgBenchmark.jl` to evaluate the commits.

Example script for running benchmarks of a package that has `BenchmarkGroup` defined in `benchmark/benchmarks.jl`:

```Julia
using PkgBenchmark # installed in root environment
using BenchmarkTools 
using LibGit2
using Printf
# activate the package benchmarking environment and run following

# Define the commits to benchmark, get this with `git rev-list <since_hash>..HEAD`
tags = [
"30242a78b4f6a2e3914610d608c602172e8968cb", # latest
"9c421b298a30deb338bc37e2dc43cdb4c17d09b7",
"76d103ee7a66e9f1619650b15d06912311212d3a",
"30c18da277921b64d70cc12271e5f83e7936e6bc",
"b10aa8696efa4a6559add82d0274412080bff4b8",
"98450a1cbcfc8ccbbbb288271729e9da19d867f7", # oldest
]
reverse!(tags)

baseline = "f6a815db026d21c144346c8b9e5c5df3548f0f61"
judgements = []
benchmarks = []

# Run the benchmarks of selected commits above
baseline_benchmark = PkgBenchmark.benchmarkpkg("MCTS", baseline; resultfile = "./dev/MCTS/benchmark/results/pkgbnch_benchmark_$baseline.json")
for target in tags
    # push!(judgements, PkgBenchmark.judge("MCTS", target, baseline; resultfile = "./dev/MCTS/benchmark/results/pkgbnch_judgment_$target.json"))
    push!(benchmarks, PkgBenchmark.benchmarkpkg("MCTS", target; resultfile = "./dev/MCTS/benchmark/results/pkgbnch_benchmark_$target.json"))
end

# Collect information about the commits
r = LibGit2.GitRepo("./dev/MCTS")
restable = """
| order | hash | time ratio | memory ratio | comment |
"""
for (i, benchmark) in enumerate([baseline_benchmark, benchmarks...])
    result = BenchmarkTools.ratio(median(PkgBenchmark.benchmarkgroup(benchmark)), median(PkgBenchmark.benchmarkgroup(baseline_benchmark)))
    trial_ratio = result["vanilla"]["gridworld"]

    commit_hash = PkgBenchmark.commit(benchmark)
    comment =  c = LibGit2.message(LibGit2.GitCommit(r, commit_hash))
    
    line = """
    | $i | $(commit_hash[1:8]) | $(@sprintf("%.2f", trial_ratio.time)) | $(@sprintf("%.2f", trial_ratio.memory)) | $(comment) |
    """
    restable *= line
end

print(restable)
```
