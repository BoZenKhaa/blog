# SSH 

## ssh config
```bash
# Example ssh config file located at ~/.ssh/config

Host myserver
    HostName server.domain.com # or IP address
    User myusername
    Port 22
    IdentityFile ~/.ssh/id_rsa_myserver
    ForwardAgent yes

```

## ssh agent

SSH-agent is awesome thing that keeps track of your keys and can be used to forward keys for use on servers. 

To add a key to ssh-agent, do:
```bash
ssh-add ~\.ssh\id_rsa
```

To list keys added, do:
```bash
ssh-add -L
ssh-add -l # more human readable
```
### Debugging ssh-agent

#### Basic check

Check if ssh-agent is running on local machine and has loaded keys:
```bash
ssh-add -l # list keys loaded in agent
```

Connect to the server with agent forwarding, either in `.ssh/config` or with `-A` flag:
```bash
ssh -A user@server
```

Then check if agent is running on server and has keys loaded:
```bash
ssh-add -l # list keys loaded in agent
```

If keys are not visible on server, check:
1. If agent is active on server:  `echo $SSH_AUTH_SOCK`, if it is empty, agent is not running
2. If the variable is set, check if you are not running a different agent, e.g. as a plugin in .zshrc


## SSH and git
To find out which key is used by git, try
```bash
ssh -vT git@gitserver.com
```
and check out the verbose log, it will say which key is being used

Anyway, this guide is better: https://docs.github.com/en/authentication/connecting-to-github-with-ssh/using-ssh-agent-forwarding 

### Setting ssh client for git
Git on windows ships with its own ssh client. This might cause issues, e.g. when adding keys to ssh-agent from Windows side, git ssh client might not see them.

To test this:
```pwsh
Get-Command ssh # shows which ssh client is being used, likely 
#C:\WINDOWS\System32\OpenSSH\ssh.exe
git config --global core.sshCommand  # shows which ssh client git is using

# set git to use Windows ssh client
git config --global core.sshCommand "C:/Windows/System32/OpenSSH/ssh.exe" 

```


### SSH and github
You can link ssh key to your github account, or to a repository as a deploy key. 

- Deploy key: can be added to a single repository only
- Account key: works with user, across all repositories

Notably, adding deploy key to an ssh-agent will block you from interacting with any other repository, so you want to remove it from ssh agent with `ssh-add -d ./.ssh/private_key` command.

### Creating new keys

Modern kind of key according to github help:

```bash
ssh-keygen -t ed25519 -C "mrkosjan@gmail.com"`
```

See github guide on adding it to agent: https://docs.github.com/en/authentication/connecting-to-github-with-ssh/generating-a-new-ssh-key-and-adding-it-to-the-ssh-agent


## SSH port forwarding

Most commonly, you want local port forwarding, which is done with `-L` flag. 
It allows you to connect to an application running on a remote server `remote` as if it was running on your local machine.



```bash 
# Forward local port 8080 to a remote server port 80:
ssh -L localhost:8080:localhost:80 user@remote

# the first localhost can be ommited, it will default to localhost
ssh -L 8080:localhost:80 user@remote

# in genneral, the syntax is:
ssh -L [local_ip:]local_port:remote_ip:remote_port user@remote_host
```

## ssh in Windows - issues

### Bad permissions
The private key should not have access by everyone, ideally just by user. 
Go to file properties -> security -> advanced -> disable inheritance -> remove all permissions except for your user.

### Other issues

#### huggingface
Hugging face will happily accept first key offered by ssh-agent, so if you have multiple keys loaded, it may pick the wrong one. So you need to configure which key to use in `~/.ssh/config` file:
```Host hf.co
  IdentityFile ~/.ssh/id_rsa_hf
  IdentitiesOnly=yes # makes sure only the specified keys is used, and not any other loaded in ssh-agent
```
