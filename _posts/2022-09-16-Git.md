# Git commands

## Rebase
```bash
git rebase master
```
Move the comments in the current branch to the selected commit passed as argument to the command.

Note that this command changes history since it moves stuff around.

## Reordering commits in a branch
```
git rebase -i HEAD~3
```
Starts an interactive rebase, where moving the commits around chnages their order. The number after `HEAD~` is the number of commits you want to rebase. The oldest commit is the first one.

# GitHooks
## Clean notebook before commit
 See https://jamesfolberth.org/articles/2017/08/07/git-commit-hook-for-jupyter-notebooks/

 ```bash
 #!/bin/sh

# Check for .ipynb files with output cells;
# ask the user if they really want to commit them
ipynb_files=`git diff --staged --name-only | awk "/.ipynb/"`
have_output=""

if [ -n "$ipynb_files" ]; then
  while read filename; do
    if [ $(git show :$filename | grep -cm1 "\"output_type\":") -ge 1 ]; then
      have_output="${have_output}"$'\n'"$filename"
    fi
  done <<< $ipynb_files
  # use here string to run in main shell: https://stackoverflow.com/a/16854326
fi

if [ -n "$have_output" ]; then
  # https://stackoverflow.com/a/10015707
  exec < /dev/tty # allows us to grab user input

  echo "You appear to be committing Jupyter notebooks"
  echo "that contain output:"
  echo "$have_output"$'\n'
  while true; do
    read -p "Proceed with commit (y/n)?: " resp
    case $resp in
      [Yy]* ) exit_status=0; break;;
      [Nn]* ) exit_status=1; break;;
          * ) echo "Please answer y or n";;
    esac
  done

  exit $exit_status
fi
 ```

## Merge conflict
If automerge cannot be done, you need to resolve merge conflict. To me, it seems the best way is to use windows git extensions a and merge through that, using VS code as merge tool. 

For example, I have a branches `main` and `feature`. I want to merge `feature` into `main`, thus having `main` holding the result. You start by checking out `main` and launching merge. 

If there is a conflict, in VS, you will see 3 tabs:
- LOCAL, the current branch (HEAD), representing `main`
- REMOTE, the branch you are merging into HEAD, representing `feature`
- The result that will be commited

There can also be `BASE` - the common ancestor of the two branches.

## How to move latest commits into a new branch
From https://stackoverflow.com/a/1628584/1400490

```bash
# Note: Any changes not committed will be lost.
git branch newbranch      # Create a new branch, saving the desired commits
git checkout master       # checkout master, this is the place you want to go back
git reset --hard HEAD~3   # Move master back by 3 commits (Make sure you know how many commits you need to go back)
git checkout newbranch    # Go to the new branch that still has the desired commits

```

## Tagging a commit and release
To make a new release on GitHub, you need to tag a commit locally and push that tag to GitHub:

```bash
git log # Find the commit hash you want to tag
git tag v1.4.0 9dghasc4 # Tag the commit without message
git push origin v1.4.0 # Push the tag to GitHub
``` 

## Making github pull request

1. Fork project on github, clone your fork to a local workstatsion
2. Make the changes you need and commit them
3. Add new remote named `myfork` to the local repository with `git remote add myfork git@github.com:<REPOSitory_NAME>`
4. Push to the new fork with `git push myfork <BRANCH NAME>`, probably just `git push myfork main`
5. In GitHub, go to the page with your pork and click "Contribute" -> "Open pull request"
